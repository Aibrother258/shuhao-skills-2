# 交互确认点总表（cross-skill）

本文件是六份 novel-* skill 的**统一交互约定**。每个 skill 在 SKILL.md 里只写自己那段确认点，
细节与总清单都引到这里。改任何一个确认点，先改本表，再同步到对应 skill。

## 0. 开工前必须和用户对齐的三件事

任何一条 novel-* 流水线（单跑或全流程）**启动第一步**就要把下面三件事摆给用户确认，
别闷头直接跑。确认完再动脚本。

| 序号 | 对齐项 | 为什么必须问 | 不确认的后果 |
| --- | --- | --- | --- |
| ① | **美术风格**（realistic / ghibli / photorealistic / comic / ink / noir） | 风格是整套管线的第一道决策，art → characters → art → script → storyboard 全链路沿用同一档，中途不能换 | 人物与场景质感对不上，合成时没法看；换风格要重跑全链路 |
| ② | **本次范围**（跑哪几层、哪几集、要不要联动上游） | 决定工作量与产物落点；全流程有 DAG 顺序，单跑要确认上游是否齐 | 跑错层 / 漏上游对账 / 产物无上游可引用 |
| ③ | **产出形态**（只要提示词 + 路径，还是也出图 / 出视频） | 本管线**只产出提示词与路径，不调用任何生图 / 生视频工具**。角色图、首帧图、视频一律由用户在别处生成后回填 | 默认不替用户生图，避免越界与额度浪费 |

对齐后用一句话向用户复述确认结果（风格 X / 范围 Y / 只交提示词不替出图），再开工。

> ⚠️ **风格记在 art 层**：第一决策点在 `novel-art` Step 0，其余 skill 只继承、不重选。
> 若从中间层（characters / script / storyboard）启动，先确认上游 art.json.style 已定且沿用。

## 1. 流程中必须用户拍板的硬卡点

以下环节**必须停下来等用户确认**，不能自作主张替用户决定（尤其是"替用户生图"）：

| 卡点 | 所在 skill / 步骤 | 要用户拍板什么 | 不拍板的后果 |
| --- | --- | --- | --- |
| **C1 大纲拍板** | novel-outline · Step 3（快版骨架 → 用户拍板） | 砍了哪条线、合了哪些人、大爆点落在第几集 | 分集写完才发现方向错，全废 |
| **C2 风格决策** | novel-art · Step 0 | 选哪一档风格（见上①） | 全链路质感基准错 |
| **C3 角色出图 / 回填** | novel-characters · Step 8 | 是否在此出图；若只交提示词，定稿后由用户回填路径 | 越界替用户生图，或参考图缺失导致下游一致性污染 |
| **C4 美术 / 道具出图** | novel-art · Step 4 | 是否在此出场景 / 道具设定图（无 codex 则跳过只交提示词） | 越界替用户生图 |
| **C5 剧本批量拍板** | novel-script · Step 0 / Step 2 | 一次写几集（默认 ≤ 3 集），小批量出快拍板 | 剧本全管线改得最凶，一次写太多推翻成本高 |
| **C6 分镜三层交付** | novel-storyboard · Step 5 / Step 6 | 一条命令出齐 JSON（Agent 用）/ HTML（人审）/ prompts（生产），明确层级，不替用户出图 | 用户不知道每层给谁用、去哪生图 |

> 其余步骤（validate 质量门、render 报告、build 推进）都是确定性脚本，**不需要**用户逐次确认，
> 但**全部跑完后要汇报一句话结果**（几集 / 几个角色 / 报告路径 / 没过的门 / 没出的图）。

## 2. 三层交付物（每次出报告都要分清）

凡是渲染报告的 skill（outline / characters / art / script / storyboard），交付物都按这三层理解：

| 层 | 产物 | 给谁 | 干什么 |
| --- | --- | --- | --- |
| **JSON** | `*.<skill>.json` | **Agent** | 机器可读，结构化、可程序化驱动下游 |
| **HTML** | `*-report.html` | **人** | 审 KPI / 质量门 / 批次 / 逐条明细，人工决策 |
| **Prompt / 路径** | `prompts/` 或 `image.*` 提示词块 | **生产** | 用户拿去别处生图 / 生视频 / 配音 |

**本管线任何阶段都不替用户生图、生视频、配音**——只交提示词与回填路径，生成与回填由用户完成。

## 3. 回填约定（用户去别处生成后回来接）

1. 报告 / prompts 里给出**可直接复制的提示词**与**建议回填路径**（如 `assets/cast/<角色名>-model-sheet.png`）。
2. 用户在别处生成定稿图，放到对应路径。
3. 改 JSON 里的引用路径即完成回填（或用手工 / 辅助脚本）。
4. 重跑 `render` / `verify` 刷新下游即可。

凡涉及"出图"的步骤，SKILL.md 必须点明：**无生图工具则整步跳过，只交提示词**。
